# Arkansas — confirmed broken (adaptive Human Verification wall)

Any Arkansas company will land in `manual_review_needed`. Confirmed, not a bug to chase.

**Official lookup:** Arkansas Secretary of State corporation search — real form lives at
https://sos-corp-search.ark.org/corps (https://www.sos.arkansas.gov/corps/search_all.php
redirects there). Dept of Finance & Administration (dfa.arkansas.gov) has no entity-status tool.

**Root cause 1 (fixed 2026-08-19):** default headless Chromium's user-agent string alone triggered
a CloudFront 403 block ("Request blocked... Generated by cloudfront") — plain fingerprint detection,
not a Turing test. Fixed generically: all Playwright `new_page()` calls in `generic.py` now pass a
normal desktop Chrome UA (`DESKTOP_USER_AGENT` in `lookup/base.py`). Confirmed via curl and Playwright
that a normal UA gets a clean 200 and the real search form.

**Root cause 2 (not fixed, by design):** once past the UA block, the site has *adaptive* protection —
repeated automated hits in a short window escalate to a Cloudflare-style interstitial
("Human Verification — Let's confirm you are human... Begin"). First request after the UA fix went
through clean; every automated request since re-triggers this. Same category as
[[project-arizona-captcha-wall]]'s CAPTCHA — an explicit human-verification step — so the same
standing decision applies: not attempting to solve/click through it.

**Manual check:** https://sos-corp-search.ark.org/corps — a normal human browsing session should not
trigger the adaptive challenge (it's rate/pattern-based against automation, not a blanket block).
